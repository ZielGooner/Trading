# Trading · BTC · XRP · SOL

BTC·XRP·SOL의 Binance USDⓈ-M 실계좌 자동매매를 제공하는 Windows 프로그램입니다. C# WinForms 화면과 Python 표준 라이브러리 기반 거래 엔진으로 구성합니다. GUI는 실계좌 단일 화면이며, 저장 데이터 백테스트는 `run.ps1`과 Python 코드로 실행합니다.

이 저장소에는 소스·테스트·전략 설정·검증에 필요한 공개 시세 데이터가 포함됩니다. 실행 파일과 가상환경은 각 PC에서 만들며, API 키·계좌 상태·개인 거래 기록·생성 보고서는 Git에서 제외합니다. GitHub에 올리는 절차는 [GITHUB_UPLOAD.md](GITHUB_UPLOAD.md)에 있습니다.

## 처음 설치하기

Windows에서 Python 3.12 이상과 .NET Framework C# 컴파일러(`csc.exe`)가 필요합니다. `build.ps1`은 Windows의 `Microsoft.NET/Framework64/v4.0.30319` 또는 `Framework/v4.0.30319`에서 컴파일러를 찾습니다. Git으로 복제하거나 소스 ZIP을 푼 뒤, 프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
# 설치된 Python으로 가상환경 생성. 외부 Python 패키지는 필요 없습니다.
python -m venv --without-pip .venv

# 소스 검사
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py"

# 실행 파일 생성 및 계좌 연결 없는 GUI 검사
.\build.ps1 -Test

# 프로그램 실행
.\Trading.exe
```

`python` 명령이 설치된 Python을 찾지 못하면 Python 실행 파일의 전체 경로를 사용합니다. PowerShell이 스크립트를 차단하면 내용을 확인한 뒤 현재 터미널에만 `Set-ExecutionPolicy -Scope Process Bypass`를 적용할 수 있습니다. 빌드는 프로젝트 폴더의 `Trading.exe`를 덮어쓰므로 실행 중인 프로그램은 먼저 종료하거나 별도 복사본에서 빌드합니다.

프로그램 실행만으로 계좌에 연결하거나 실거래를 시작하지 않습니다. API 설정과 조회 연결 후, **실거래 시작**을 직접 눌러야 합니다. `strategy.json`의 `orders_enabled: false`는 저장 자료 백테스트용 설정이며 GUI의 실거래 시작 권한과는 별도입니다.

### 기능별 추가 환경

| 기능 | 필요한 환경 |

## 실계좌 연결과 자동매매

1. `Trading.exe`의 **API 설정**에서 Binance HMAC API Key와 Secret을 입력합니다. 읽기와 선물 거래 권한을 사용하며 출금 권한은 필요 없습니다. 키는 채팅에 보내지 않습니다.
2. **실계좌 연결**을 눌러 실제 지갑·가용 증거금·포지션을 확인합니다. 이 단계는 조회만 수행합니다.
3. **실거래 시작**을 누르면 실제 주문이 가능해집니다. 단방향(One-way), 단일 자산 USDT 계정이 필요합니다. 빈 종목의 격리 모드와 BTC 10배·XRP/SOL 5배를 설정·확인하며 자동 증거금 추가가 켜져 있으면 시작하지 않습니다.
4. **신규 진입 중지**는 새 포지션만 중지하고 기존 포지션을 관리합니다. **연결 해제/프로그램 종료**는 진행 중인 처리를 마친 뒤 종료하며, 이미 거래소에 등록된 TP/SL은 남습니다. 재실행은 조회 상태이며 **실거래 시작**으로 관리를 복구합니다.

실거래는 실제 계정의 **진입 직전 가용 증거금 10%**를 기본으로 수량을 내림 처리하며 진입 수수료 여유를 포함합니다. **최소 주문 금액·수량에 미달하면 조건을 충족하는 최소 수량까지 올림하여 10% 초과를 허용합니다.** 매 진입 시 Binance 거래 규칙을 새로 조회하고 지정가·시장가 수량 단위를 함께 맞춥니다. 필요한 증거금+진입 수수료가 실제 가용 잔고를 초과하거나 거래소 수량·명목 한도를 넘으면 건너뜁니다. 보정 수량과 예상 증거금 비율은 실계좌 로그에 표시되며, 체결 후 검사와 재시작 복구에도 해당 한도가 유지됩니다. 부분 체결에는 추가 매수/매도를 하지 않습니다. 백테스트의 1,000 USDT는 실계좌 자금 한도가 아닙니다. 최대 명목 50,000 USDT, 종목당 한 포지션, BTC→XRP→SOL 순서입니다. 다른 봇/수동 거래와 같은 종목을 함께 사용하지 마세요. 출처가 다른 기존 포지션·주문은 신규 매매 시작을 막습니다.

완료된 Binance 4시간봉만 사용하고 **시작 이후 다음 완료봉부터**, 봉 마감 후 90초 안에만 IOC 지정가로 진입합니다. TP/SL은 체결 가격·실제 체결량에 맞춘 거래소 조건부 시장가 `reduceOnly` 주문입니다. 부분 체결도 보호하며, 보호 주문이 누락/거부되면 신규 진입을 멈추고 프로그램 소유 포지션의 축소 청산을 시도합니다. 통신 장애에서는 체결·보호를 보장할 수 없으므로 화면 오류가 지속되면 Binance에서 직접 확인해야 합니다.

초기 지표는 최근 약 1,500개 Binance 봉으로 준비하고 이후 누적합니다. 저장된 TradingView 백테스트와 데이터 출처·초기 구간·체결 가격이 달라 실거래 결과는 동일하지 않습니다. 계좌/포지션/보호 주문은 REST로 약 5초마다 확인합니다. 최대 보유 32일 청산과 오류 복구는 프로그램이 연결되어 있어야 작동합니다. 일중 3% 진입 차단은 UTC 날짜별 첫 연결/관측 시점의 실제 USDT 자산을 기준으로 저장하며, 입출금도 이 값에 영향을 줍니다.

API 키는 Windows DPAPI로 암호화한 `private_state/binance-credentials.dpapi`에 저장됩니다. 이 Windows 사용자 계정에서만 복호화하며, 로그·명령행 인자·백테스트 보고서에는 키를 기록하지 않습니다. `private_state`의 주문 상태는 재시작 시 중복 주문 방지에 필요하므로 실제 포지션이 있는 동안 삭제하지 마세요.

[Binance 계좌 API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/account), [주문·TP/SL API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade), [서명·오류 처리](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)를 기준으로 구현했습니다.


## 거래 내역 엑셀과 Codex 분석

실계좌 화면 오른쪽 위 **거래 내역 · 분석** 버튼을 누릅니다.

1. **내역 새로고침**: 저장된 API로 BTC·XRP·SOL 체결·수수료·펀딩을 조회하고 엑셀에 저장합니다. 주문 전송은 없습니다.
2. **엑셀 저장·열기**: 현재 로컬 원장으로 엑셀을 갱신하고 엽니다. 저장 위치는 `records/<계정ID>/거래내역.xlsx`입니다.
3. **7일 / 30일 / 90일** 버튼이나 일수 입력(1~365일)으로 기간을 정하고 **Codex 분석**을 누릅니다. 취소 버튼도 제공합니다.
4. 피드백은 화면과 `records/<계정ID>/analysis/`에 Markdown·근거 JSON으로 남습니다. 현재 전략에는 자동 적용하지 않습니다.
5. **Codex 대화** 탭에서 질문을 입력한 뒤 **질문 보내기** 또는 **Ctrl+Enter**를 누릅니다. Enter는 줄바꿈입니다. 한 질문은 최대 4,000자이며 답변 중에는 취소할 수 있습니다.
6. 대화는 선택 기간의 최신 로컬 거래내역·현재 전략·동일 기간의 최근 분석 보고서를 참고합니다. **새 대화**를 누르거나 기간·계정을 바꾸면 새 문맥으로 시작합니다. 창을 닫아도 성공한 대화 기록은 계정별 chat 폴더의 JSON 파일에 남습니다. 다시 연 창은 새 대화로 시작합니다.

실계좌 연결 중에는 별도 조회 작업이 약 1분 간격으로 원장과 엑셀을 갱신합니다. 엑셀이 열려 갱신이 막혀도 원본 체결은 SQLite에 보관하며, 파일을 닫으면 다음 저장 때 반영합니다. 프로그램이 닫힌 동안 체결된 거래도 다음 조회 때 가져옵니다. 최초 조회는 최근 89일이며 이미 로컬에 저장한 내역은 계속 누적합니다. 3개월 이전의 미수집 기록은 REST 조회로 복원하지 못하며, 누락 구간은 분석에 표시합니다.

엑셀은 **요약 / 거래내역 / 체결원장 / 펀딩** 네 시트입니다. 거래 ID는 텍스트로 보관해 긴 숫자가 반올림되지 않습니다. 날짜는 KST, 금액은 자산 단위를 표시합니다. 원시 체결에는 수동·외부 거래도 포함합니다. 프로그램의 진입 주문과 연결되고 진입/청산 수량 및 USDT 수수료·펀딩이 확인된 완료 거래만 전략 통계에 사용합니다. 연결 정보를 보관하지 않았던 과거 거래는 계좌 전체 활동으로 분석하며 현재 전략의 성과로 단정하지 않습니다. 비USDT 수수료는 원장에 원래 자산으로 남기고, 환산이 필요한 거래의 전략 순손익·승률 계산은 보류합니다.

기간은 청산 시각 기준의 최근 N일입니다. 완료 거래 통계에는 그 거래 전체 보유기간의 비용을 포함합니다. 계좌 활동은 선택 기간 안의 현금흐름으로 따로 표시합니다. 계좌 수익률이나 미실현손익 포함 낙폭을 추정하지 않습니다. 전략 입력에는 저장 자료 재생용 1,000 USDT와 `orders_enabled` 스위치를 제외하여 실계좌 상태와 혼동하지 않게 합니다.

분석은 설치된 **Codex CLI의 ChatGPT 로그인**을 사용합니다. 모델은 **`gpt-6-astra`**, 추론 강도는 **Extra High(`xhigh`)**로 고정합니다. 다음 분석 실행부터 적용되며, 분석 화면과 새 보고서에도 설정을 표시합니다. 로그인이 없으면 **Codex 로그인**을 누릅니다. 별도 API 키나 다른 유료 공급자로 대체하지 않습니다. 분석 통계·최근 체결의 가격/수량/비용·전략 설정을 Codex에 전달하며 Binance API 키, 계정 ID와 주문 ID는 전달하지 않습니다. 읽기 전용, 도구 비활성화, 별도 임시 작업 폴더에서 실행합니다. 거래가 없으면 기간별 자동 분석을 호출하지 않습니다. 직접 질문하는 대화에서는 전략 설명을 받을 수 있지만 없는 성과를 생성하지 않습니다. 대화 문맥은 최근 10쌍(최대 60,000자)을 참고하고, 생략이 생기면 표시합니다. 질문 입력란에 작성한 내용도 Codex에 전송됩니다. Windows 입력 파이프에는 ASCII JSON 이스케이프를 사용하여 한글·이모지·줄바꿈을 보존합니다. 업데이트 전에 열었던 창은 프로그램을 종료하고 새 Trading.exe를 실행해야 새 전송 방식이 적용됩니다.

엑셀 생성은 설치된 Codex 번들의 Node.js와 Artifact Tool을 사용합니다. Python 외부 패키지 설치는 필요 없습니다. `private_state/history-<계정ID>.sqlite3`는 중복 방지와 원본 내역 보존에 사용하므로 삭제하지 마세요. 엑셀 수동 편집 내용은 다음 자동 저장에서 덮어씁니다.

근거: [Binance 체결 API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade), [펀딩·수입 내역 API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/account), [Codex 비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode).

## 실행

**프로젝트 폴더의 `Trading.exe`를 더블클릭**하면 실계좌 화면이 열립니다. API 설정·계좌 연결·자동매매 제어를 이 화면에서 사용합니다. 백테스트 메뉴와 실행·결과 화면은 제공하지 않습니다.

화면은 [Binance 거래 화면](https://www.binance.com/en/trade)을 참고한 차콜·옐로 테마를 사용합니다. 중앙 차트·포지션과 오른쪽 계좌·자동매매 제어를 나눠 표시합니다. 연결 전에는 계좌 값이 `—`로 표시되고 실거래 시작 버튼은 비활성화됩니다.

차트는 `data`에 저장된 BTC·XRP·SOL의 완료된 4시간봉, MA20, 거래량을 표시합니다. 실시간 시세가 아니며 차트에 저장 데이터 표시와 UTC 시각을 제공합니다. 종목 버튼으로 전환해도 계좌 연결이나 주문은 실행하지 않습니다. 자료가 없거나 잘못된 경우 대체 가격을 만들지 않고 자료 없음 상태를 표시합니다.

이 EXE는 같은 프로젝트 폴더의 `.venv`와 소스·데이터 파일을 사용하는 Windows 실행 창입니다. 다른 PC에서는 저장소 전체와 위 설치 과정이 필요합니다.

## 개발용 백테스트

GUI에서 제거한 백테스트는 개발·검증용 명령행 도구로 유지합니다. PowerShell의 프로젝트 폴더에서 실행합니다:

```powershell
.\run.ps1
```

현재 포트폴리오만 계산하며 `reports/REPORT.md`와 `reports/summary.json`을 갱신합니다. 과거 실행 로그를 쌓지 않습니다.

```powershell
# 종목별·비용·자료불일치 등 8개 시나리오와 정리 전후 동일성 확인
.\run.ps1 --verify

# 현재 거래·이벤트·시간별 자산을 압축 JSON으로 추가 저장
.\run.ps1 --details

# 현재 코드 검사
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py"
```

`--verify`는 현재 저장된 전략·자료와 정리 전 실행의 정확한 동일성을 검사합니다. 설정을 직접 바꾼 경우 기본 실행 또는 `--all`로 계산합니다. `--details`를 생략하면 이전 상세 원장을 제거하고 요약만 유지합니다.

## 현재 전략

아래 저장 백테스트는 기존 10% 규칙의 과거 결과이며, 실계좌의 최소 주문 보정 예외는 반영하지 않았습니다.

백테스트 초기1,000USDT. 모든 진입은 **진입 직전 가용 증거금의10%**, BTC10배·XRP/SOL5배. 종목당 한 포지션, 최대3개. BTC→XRP→SOL 순으로 증거금과 진입 수수료를 차감합니다. 재진입 대기는 없습니다.

| 종목 | 진입 | SL | TP |
|---|---|---|---|
| BTC | Supertrend12·승수3, ADX14≤20 | 3.5ATR21 | 8R |
| XRP | Supertrend17·승수1.8 | 3.5ATR21 | 8R |
| SOL | EMA48 종가 돌파, EMA50 방향·기울기 및 ADX14≥10 | 2.5ATR21 | 6R |

완료4시간봉의 롱/숏 신호를 다음1시간 시가에 실행합니다. 최대보유는192개4시간봉(32일). R은 최초손절 거리입니다. 가용증거금에는 기존 격리증거금·미실현손익을 포함하지 않습니다. 일중손실3% 이후 신규진입 차단, 격리손실 제한, 수량단위·최소명목, 비용·공개펀딩을 적용합니다.

현재 저장758일(2024-08-27~2026-09-24)의 합산 모의 결과는 수익률 **+2,295.03%**, 승률 **53.12%**, 최대낙폭 **22.94%**입니다. 시간별 Mark 종가 기준이며 과거 최적화 결과입니다. 후반228일에서 합산낙폭은 이전19.62%보다 높은22.25%였고, 일부 인접설정의 성과가 크게 악화됐습니다. 미래 수익성 검증이 아닙니다.

## 파일

- [strategy.json](strategy.json): 현재 전략 및 고정 자금 조건.
- `Trading.exe`: 로컬 빌드로 만드는 더블클릭 실행 창. Git 제외.
- `app/TradingLauncher.cs`, `app/LivePanel.cs`, `app/MarketChart.cs`, `app/Theme.cs`, `build.ps1`: 실계좌 단일 실행 창·저장 차트·공통 UI와 빌드 명령. `./build.ps1`로 다시 빌드하며 추가 패키지는 필요 없습니다. `./build.ps1 -Test`는 백테스트 UI 제거, 미연결 상태의 거래 비활성화, 3종목 저장 차트와 DPAPI 암호화를 검사합니다. 계좌 연결·주문·백테스트 실행은 수행하지 않습니다. `-Test -Preview`는 `reports`에 기본·축소 화면 미리보기도 저장합니다. 백테스트 동일성은 개발용 `./run.ps1 --verify`로 별도 검사합니다.
- `trading/`: 지표·백테스트·원장 감사·Binance REST 연결·실계좌 실행 코드.
- `private_state/`: API 암호문, 주문 복구 상태, 누적 봉 및 영구 거래 원장. Git 제외.
- `records/`: 계정별 거래 내역 엑셀과 Codex 피드백. Git 제외.
- `app/HistoryForm.cs`, `app/export_history.mjs`, `trading/history.py`, `trading/review.py`: 거래 내역·분석 화면, 엑셀 생성, 원장·통계와 Codex CLI 연결.
- `data/`: 실행과 출처·교차자료 검증에 필요한 공개 원본14개. BTC1h 및 보완파일3개도 실행자료의 원본해시 연결 검증에 필요합니다.
- `tests/`: 현재 코드 검사와 정리 전 실행의 비교 지문.
- `reports/`: 로컬 보고서·화면 미리보기·백업. Git 제외. `run.ps1`을 실행하면 현재 결과인 `REPORT.md`와 `summary.json`을 생성합니다.
- `.venv/`: 각 PC에서 만드는 외부 Python 패키지 없는 실행 환경. Git 제외.
- `.gitattributes`: 소스 줄바꿈 규칙. 원본 해시를 검사하는 `data/` 파일의 바이트는 보존합니다.
- [GITHUB_UPLOAD.md](GITHUB_UPLOAD.md): 첫 업로드와 이후 변경 사항 업로드 절차.

BTC/XRP의 알려진 교차자료 불일치는 각1개입니다. 원본을 보정하지 않고 증거파일과 별도 시나리오로 확인합니다. Mark청산→SL→TP 봉내순서, 유지증거금률1% 등 모형 가정이 실제체결과 다를 수 있습니다. 개발용 백테스트 명령은 저장자료를 재생합니다. 실계좌 화면의 계좌 연결은 별도로 Binance의 최신 데이터를 조회하며, 화면 차트는 저장자료를 표시합니다.

환경을 다시 만들 때는 설치된 Python3.12 이상으로 `python -m venv --without-pip .venv`를 실행하면 됩니다. 추가 패키지는 필요 없습니다.

## 실계좌 기능 검증 상태

개발 환경의 기존 검증 기록에는 Python 검사 128개, GUI·DPAPI 검사, 저장 백테스트 8개 시나리오 동일성 검증이 포함되어 있습니다. 공개 API 조회, 사용자 환경의 거래·펀딩 조회와 엑셀 저장, Codex 로그인·분석·연속 대화도 이전에 확인했습니다. 당시 기록은 로컬 `reports/live_validation.json`에 보관하며 Git에는 포함하지 않습니다.
