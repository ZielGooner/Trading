# AUREX (Trading)

현재 버전은 **v2**입니다. 이전 소스는 [v1 Release](https://github.com/ZielGooner/Trading/releases/tag/v1), 새 소스는 [v2 Release](https://github.com/ZielGooner/Trading/releases/tag/v2)에서 내려받을 수 있습니다. 버전별 변경 내용은 [CHANGELOG.md](CHANGELOG.md)를 참고하세요.

Windows에서 Binance USDⓈ-M 선물 계좌를 연결하고 BTC·XRP·SOL·HYPE의 확정봉 전략을 실행하는 프로그램입니다. 실행 직후에는 연결되지 않은 상태이며, 계좌 연결만으로 신규 주문을 보내지 않습니다. **실거래 시작**을 눌러야 신규 진입을 시작합니다.

## 실행과 계좌 설정

프로젝트 폴더의 `Trading.exe`를 더블클릭합니다. 다른 PC에서는 Python 3.12 이상과 Windows .NET Framework가 필요합니다.

창 이름과 아이콘은 **AUREX**입니다. 상단의 **메인 / 거래 내역 / 분석**으로 같은 창 안에서 전환하며, 탭을 바꿔도 계좌 연결·시장 시세 수신·입력한 대화는 유지됩니다. 메인에는 계좌·차트·포지션·매매 제어가, 분석에는 기존 분석 보고서와 Codex 대화가 있습니다.

화면 글꼴은 **Pretendard**입니다. 제목·버튼은 Bold, 본문·거래 목록·차트·입력 필드는 Regular를 사용하며 글꼴이 실행 파일에 내장되어 별도 설치나 다운로드가 필요 없습니다. 공식 SIL OFL 1.1 라이선스에 따라 무료 사용·상업용 앱 내장·재배포가 가능합니다. 원본 글꼴과 고지는 `app/fonts/`에 있으며 실행 파일을 배포할 때는 빌드가 함께 생성한 `Trading.font-license.txt`도 포함하세요.

거래 내역 엑셀 생성에는 설치된 Codex 번들의 Node.js와 `@oai/artifact-tool`도 필요합니다. 사용자 홈 아래 `.cache/codex-runtimes/codex-primary-runtime/dependencies`에서 이를 찾으며, 번들이 없으면 엑셀 생성 오류를 표시합니다. 이 런타임은 저장소에 포함하지 않습니다.

```powershell
python -m venv --without-pip .venv
.\build.ps1
```

1. **API 설정**에서 Binance USDⓈ-M 선물용 HMAC 키를 저장합니다. 읽기·선물 거래 권한을 사용하며 출금 권한은 필요 없습니다.
2. **실계좌 연결**로 계좌 잔액·포지션·주문 상태를 확인합니다.
3. **실거래 시작**을 누르면 시작 이후 완료되는 4시간봉부터 진입 조건을 확인합니다.
4. **신규 진입 중지**는 새 포지션 진입을 멈춥니다. 프로그램이 관리하는 기존 포지션의 보호·종료 처리는 계속됩니다.

지원 계좌는 USDT 기준의 단방향·격리마진입니다. 같은 종목의 수동·외부 주문과 프로그램 주문이 섞이면 소유권을 확인할 수 없으므로 시작 조건을 충족하지 못할 수 있습니다. API 키는 해당 Windows 사용자 계정으로 암호화해 `private_state/binance-credentials.dpapi`에 저장합니다.

## 현재 4종목 전략

전략 버전은 `TV_BASE_4ASSETS_2X_20261005`입니다. 네 종목 모두 **4시간봉에서 실행**하고 확정된 상위 시간봉으로 조건을 확인합니다. 상위봉은 신호 4시간봉의 시작 시각까지 마감된 마지막 봉을 사용합니다. 아직 끝나지 않은 상위봉은 사용하지 않습니다. 조건부 반익절·runner 후보는 이번 프로그램에 적용하지 않았습니다.

| 종목 | 진입 조건 | 확정 상위봉 | TP / SL | 보유 제한 |
|---|---|---|---|---|
| BTC | BB(14, 1.5) 상단 위 종가 롱, 하단 아래 종가 숏 | 8시간 ADX(14,14) < 25 | 1 / 1.25 ATR14 | 3봉, 필터를 충족하는 반대 신호 종료 |
| XRP | 직전 2봉 최고가 위 종가 롱, 최저가 아래 종가 숏 | 일봉 종가와 EMA10 방향 | 1.5 / 1.25 ATR14 | 3봉, 필터를 충족하는 반대 신호 종료 |
| SOL | EMA2/8 교차 | 8시간 EMA5/20 방향 | 1 / 3 ATR14 | 6봉, 반대 신호 종료 없음 |
| HYPE | BB(8, 1.5) 하단 상향 복귀 롱, 상단 하향 복귀 숏 | 12시간 EMA5/20 방향 | 0.5 / 1.5 ATR14 | 시간·반대 신호 종료 없음 |

ATR14는 신호 봉에서 고정합니다. TP/SL은 실제 체결가격을 기준으로 틱에 맞추고 실제 체결량을 보호합니다. 종목별 추가 진입과 같은 시가에서의 즉시 반전 진입은 하지 않습니다. 보유 제한은 진입 봉을1로 세며, 제한 봉 마감에서 종료를 예약합니다.

## 공유자금 배분

모든 종목의 레버리지는 **2배**입니다. 같은 시점 신호는 **직전 확정4시간봉의 거래량×종가**가 큰 순서로 처리합니다. 이는 코인별 수량 단위를 맞춘 **USDT 거래대금 근사**이며 동률은 심볼 사전순입니다.

각 체결 후 남은 가용자금을 다시 확인하고 **그50%를 초기증거금으로 요청**합니다. 실제 진입 명목은 배정 증거금의2배입니다. 예를 들어 비용을 제외하면 첫 신호가 시작 가용자금의50%, 다음 신호가 남은50%의50%를 사용합니다. 계좌 전체 명목의50%를 주문하는 규칙이 아닙니다.

같은 시점에 여러 종목을 처리할 때는 확정 체결의 증거금·수수료도 프로그램에서 차감합니다. 거래소 잔액 갱신이 늦으면 이 차감 잔액과 거래소 잔액 중 작은 값을 사용해 같은 자금을 다시 배정하지 않습니다.

수수료·담보·진입 직후 총명목2배 상한에 따라 주문량을 축소합니다. 최소 주문량·최소명목을 채우지 못하면 해당 진입을 건너뜁니다. 최소 주문을 맞추려고 비중을 늘리지 않습니다. 보유 중 가격 변화에 따른 총노출은 진입 시2배 제한과 다릅니다. 이전 일중3% 신규 진입 제한은 제거했습니다.

완료봉을 확인한 뒤 허용 시간 안에 IOC 지정가로 진입합니다. TP/SL은 거래소의 축소 전용 보호 주문으로 관리합니다. 보호 주문 누락·거부나 계좌 정보 오류가 발생하면 신규 진입을 중지합니다. 통신 중단 시 체결·보호를 보장할 수 없으므로 지속되는 오류는 거래소 계좌에서 확인해야 합니다.

## 차트와 거래 기록

중앙 차트는 **Binance 공개 USDⓈ-M 선물 시세**에 연결합니다. 처음 최근 봉을 조회하고, 이어서 도착하는 시세로 차트를 갱신합니다. BTC·XRP·SOL·HYPE와 **15분·1시간·4시간·일봉·주봉**을 선택할 수 있습니다. 공개 시세 연결에는 계좌 연결이나 API 키가 필요 없으며 주문을 실행하지 않습니다.

마지막 진행 중인 봉의 가격·고가·저가·거래량은 새 응답에 따라 바뀝니다. UTC 봉 시각과 조회 상태를 표시하며 조회 실패·오래된 자료를 정상 시세처럼 표시하지 않습니다. 아직 조회한 자료가 없으면 자료 없음 상태를 표시하고 대체 가격을 만들지 않습니다.

차트에 마우스를 올리면 선택한 봉의 **시가·고가·저가·종가·변화·거래량이 차트 위쪽에서 갱신**됩니다. 별도 툴팁 상자를 띄우지 않습니다. 십자선과 오른쪽의 마우스 위치 가격, 하단 봉 시작 시각(UTC)을 표시하고, 마우스가 나가면 최신 봉 값으로 복원합니다. 종목·시간봉을 바꾸면 이전 호버 선택을 지웁니다. 포지션 방향 표기는 **long / short**입니다.

차트 종목과 시간봉 선택은 화면 표시만 바꿉니다. 자동매매의 **4시간 실행·확정 상위봉 확인·2배 진입·TP/SL 규칙은 그대로**입니다. 차트의 진행 중인 봉을 전략의 확정 신호로 사용하지 않습니다.

**거래 내역**에서는 시작일·종료일·심볼을 선택하고 최신순으로 **20개씩** 조회합니다. 날짜는 한국 시간(KST), 시작일·종료일 모두 포함하며 최대 365일입니다. 기본 **완료 거래**는 프로그램 기록과 연결된 포지션을 청산 시각 기준으로 표시합니다. **전체 체결**은 수동·외부 체결도 포함하며, BUY/SELL만으로 long/short를 추정하지 않습니다. 미확인 가격은 `—`로 표시합니다. 목록의 실현 손익은 비용 반영 전이며, 분석의 순손익과 구분합니다.

기간 달력·심볼·거래 보기 선택은 같은 다크 테마를 사용합니다. 달력에서 월 이동과 오늘 선택을 지원하며 방향키·PageUp/PageDown·Enter로 날짜를 선택할 수 있습니다. 날짜를 직접 입력할 수도 있습니다. 선택 패널은 현재 창 안에서 열리고 바깥 클릭·Esc·탭 전환·창 비활성화 시 닫힙니다.

입력·선택·버튼과 차트·목록·보고서·대화 영역은 공통 8px 둥근 모서리를 사용합니다. 날짜·일수 입력은 실제 글꼴 줄 높이를 기준으로 세로 중앙에 배치하며, 세부 설정 제목에는 위쪽 12px 여백을 둡니다.

탭 진입·페이지 전환·조회는 저장 원장을 읽습니다. **내역 새로고침**은 거래소 자료를 동기화하고, **엑셀 저장·열기**는 전체 원장의 엑셀을 생성합니다. 읽기 작업은 주문을 전송하지 않습니다. 원본은 계정별 SQLite에, 엑셀은 `records/<계정ID>/거래내역.xlsx`에 저장합니다. 엑셀이 열려 저장을 못해도 원본 체결은 보존합니다. 최초 REST 조회는 최근89일이며 이전에 저장한 기록은 계속 유지합니다.

거래 내역 엑셀은 요약·거래내역·체결원장·펀딩의 네 시트입니다. 프로그램 진입과 연결되고 수량·USDT 비용이 확인된 완료 포지션만 전략 통계에 사용합니다. 수동·외부·귀속 미확인 거래는 계좌 활동으로 구분합니다. 과거 전략의 기록과 `strategy_version` 해시는 삭제하지 않으며 **현재 설정 버전의 성과와 과거 버전별 성과를 구분**합니다. 기간은 청산 시각 기준이고 각 거래 전체 보유기간의 비용을 포함합니다.

분석 기간은 거래 내역의 선택 필드와 같은 디자인의 숫자 입력(스핀 박스)으로 1~365일을 지정합니다. 직접 입력·위아래 화살표·7/30/90일 버튼을 지원하며 기간을 바꾸면 이전 분석·대화 문맥을 초기화합니다.

Codex 분석·대화는 설치된 Codex CLI의 ChatGPT 로그인을 사용합니다. 현재 전략과 선택 기간의 저장 거래 자료로 설명·개선 가설을 제공하며 자동으로 전략이나 주문을 변경하지 않습니다. 거래 자료가 없으면 성과를 생성하지 않습니다. 계정 ID·주문 ID·API 키는 분석에 전달하지 않습니다. 기본 모델은 `gpt-6-astra`, 추론은 `xhigh`입니다. 한글·이모지·줄바꿈을 보존하며 Enter는 줄바꿈, Ctrl+Enter는 질문 전송입니다.

## 검증과 파일

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py"
.\build.ps1 -Test
# 화면 미리보기도 저장
.\build.ps1 -Test -Preview
# 현재 실행 파일을 유지한 채 후보 빌드 검사
.\build.ps1 -Test -Preview -OutputDirectory .ui-update\candidate
```

GUI 검사는 네트워크 없는 모의 시세로 4종목·5시간봉 전환, 진행 중인 봉 갱신, 조회 실패·지연 표시와 미연결 상태의 거래 차단을 확인합니다. 선택 UI의 바깥 클릭·다시 열기 100회, 탭 전환·창 종료·날짜와 심볼 선택도 검사합니다. 한글 전송과 API 키 암호화 검사도 유지합니다. 계좌 연결과 실주문은 실행하지 않습니다. 후보 빌드를 적용한 뒤 이미 실행 중인 창은 종료하고 다시 실행해야 변경 내용이 반영됩니다.

- `strategy.json`: 현재 4종목 BASE 설정과 배분 규칙.
- `trading/`: 지표·확정봉 신호·실계좌 실행·원장과 분석 연결.
- `app/`, `build.ps1`: Windows 화면과 빌드.
- `data/`: 과거 공개 저장 시세. 현재 화면 차트는 Binance 공개 조회를 사용합니다.
- `private_state/`: API 암호문·주문 복구 상태·누적 봉·계정 원장. 삭제하지 마세요.
- `records/`: 거래 내역 엑셀·분석·대화 기록. 삭제하지 마세요.
- `reports/`: 이전 보고서·검증 자료·화면 미리보기. 과거 성과는 현재 프로그램의 성과를 뜻하지 않습니다.
- `tests/`: 실계좌 주문 없이 수행하는 검사.

이전 전략과 저장 자료 재생 코드는 현재 실행 경로에서 제거했습니다. 과거 계정 기록·개인 상태·보고서는 보존합니다. 저장 연구 수익률은 실제 계좌의 체결·펀딩·수량단위·가격 차이를 검증한 실거래 수익률이 아닙니다. 현재 프로그램의 실제 주문 체결이나 수익성을 이 검사로 보장하지 않습니다.

소스 업로드는 [GITHUB_UPLOAD.md](GITHUB_UPLOAD.md)를 참고하세요. 실행 파일·API 키·계정 기록은 공개 소스에 포함하지 않습니다.
